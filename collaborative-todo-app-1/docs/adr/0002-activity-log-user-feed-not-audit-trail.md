# Activity log is a high-signal user feed with a compliance-ready schema, not a full audit trail

The board Activity log primarily answers "what happened on this board recently?" for teammates — so the taxonomy logs only collaboration-relevant events (board renamed, membership changes, todo created/deleted/status/assignee changed, comment created/deleted, tag created/deleted) and deliberately skips field-level noise (title/description/priority/due-date edits, comment edits, drag reorders). The model nonetheless stores `resourceType`, `resourceId`, `actorId`, `createdAt`, and `ipAddress` from day one so a future SOC 2 requirement widens via code changes only, never a migration. Accepted gap: mutations not logged at write time are unrecoverable history — if compliance ever mandates full-field audit, those past events cannot be reconstructed. Rejected alternative: logging every mutation (drowns the user feed in noise and grows storage unbounded).
